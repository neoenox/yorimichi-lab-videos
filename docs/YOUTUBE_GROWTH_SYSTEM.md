# クリック率と視聴維持率を設計するYouTubeコンテンツ戦略システム

このリポジトリの制作標準（[`shorts-standard/README.md`](shorts-standard/README.md)）と動画制作前確認（[`docs/VIDEO_CREATION_PRECHECK.md`](docs/VIDEO_CREATION_PRECHECK.md)）を前提にした、30〜45秒のShorts向け設計。事実は出典照合が済んだものだけを使い、未確認の数字・発言・因果関係は台本に書かない。

## 1. システム全体の流れ

1. 題材の既出チェック（台帳 `data/youtube_ids.json` と `docs/` 全体を grep）
2. 条件設定と需要の下調べ（最終決定はユーザー）
3. 候補出しと相互評価、一次史料の関門
4. 1動画1疑問に絞り、前提を崩す一文と結論の方向性を決める
5. フック・タイトル・サムネイル・冒頭シーンを同じ約束事で作る
6. 5〜7シーンに分割し、ナレーション・字幕・映像・根拠IDを一対一で対応させる
7. JSONを形式検査し、出典照合と実聴・スマホ可読性を人が確認して公開

## 2. アイデアの選び方（なぜ視聴者を引きつけるか）

- **問いが1行で書けること**。标题が「なぜ？」で終わらず、視聴者が信じている前提を否定する一文になる題材を選ぶ。人は自分の思い込みが裏切られる瞬間に止まる。
- **答えの半分だけを先出しすること**。全てを出せば離脱し、何も出さなければ信頼されない。冒頭8秒で「結論の方向性」だけを示し、理由は後で回収する。
- **一度に見せられる変化が1つであること**。工程や地図の累積表示は、基準状態→変化1つ→保持、の順にする。同時に複数の変化を出すと理解が止まり、離脱につながる。
- **制作側の強みが生きること**。地形・経路・位置関係・模式図で確かめられる題材は、静止画と字幕だけの動画より「自分で確かめている」感が出る。

## 3. フック（irresistible な導入）

型は1つ。「視聴者が信じている前提を否定する一文」で始め、疑問形で終わらせない。

- 0〜3秒：前提を崩す一文。例：「実は、厚生労働省に2リットルの目安はありません。」
- 3〜8秒：結論の方向性。答えの半分だけを出す。
- 8秒以降：なぜそうなのかを、根拠と一緒に回収する。

なぜ効くか：視聴者は「自分は知っているつもり」の話をスクロールし、その思い込みが否定された瞬間に立ち止まる。さらに方向性を先に出すことで、最後まで見れば答えが揃うという見通しが立ち、離脱が減る。

## 4. タイトル

- 1動画1疑問を、そのままタイトルにする。長くても65文字以内（スキーマ上限）。
- 煽り、根拠のない最上級、「誰も知らない」系の決まり文句は使わない。
- 前提を否定する形か、数字を先に置く形にする。

なぜ効くか：タイトルは検索とCTRの両方に効く。問いが明確だと「これは自分の疑問だ」と認識され、数字や否定形はサムネイルと同じ約束事で目を引く。根拠のない最上級は信頼を削るので使わない。

## 5. サムネイルのコンセプト

- 1つの対象と1つの数字だけを置く。3つ以上要素を並べない。
- 数字を先に置き、根拠の図は別の瞬間に見せる（PROMPT.mdルール4）。
- 背景には内容に合う画像を使い、単色や図形だけにしない。生成画像・模式図は「イメージ」「模式図」と明示する。
- スマホの320×180相当で、主題・数字・出典の優先順位が残るか確認する。

なぜ効くか：サムネイルは「何の話か」と「なぜ今見るか」を一瞬で伝える。要素が多いと何が主役か読めず、数字だけ置いても根拠が見えないと信頼されない。小さくしても読める情報だけを残す。

## 6. 冒頭シーン

- 0〜3秒の画面は、否定する前提そのものを被写体にする。抽象的なロゴや抽象アニメーションで始めない。
- 3〜8秒で、結論の方向性に対応する図や数字を1つ出す。
- カメラの大きい移動・ズームは導入と離脱に寄せ、説明中は止めるか非常にゆっくり動かす。

なぜ効くか：最初の数秒で「話の対象」が画面に無いと、視聴者は文と画面の対応を探しに行き、その隙に離脱する。対象を先に見せ、説明中は動きで情報を壊さない。

## 7. 物語の構成（5〜7シーン）

| 役割 | 時間の目安 | 中身 |
| --- | --- | --- |
| 前提を崩す | 0〜3秒 | 信じている前提を否定する一文 |
| 結論の方向性 | 3〜8秒 | 答えの半分の先出し |
| 根拠1 | 8秒〜 | 一次史料または専門書で確認した事実 |
| 根拠2 | その後 | 変化を1つだけ加え、保持時間を取る |
| 回収 | 最後 | 冒頭の言葉につながる一文 |

- 1シーン3〜9秒、隙間・重複なく接続する。
- ナレーションは1秒あたり約4〜5.5日本語文字を目安にし、実測音声で最終調整する。
- テロップはナレーションの言い直しにせず、キーワードと数字だけ。1画面2行以内、1行14文字以内。
- 主張は最大3つ。最後は冒頭につながる一文で回収する。

なぜ続きを見たくなるか：視聴者は「先出しされた半分の答え」と「まだ出ていない理由」の隙間を埋めに進む。根拠が段階的に1つずつ出るので、次のシーンが何をするか予測でき、予測が裏切られない限り進み続ける。

## 8. 視聴維持のテクニック

- **回答の遅延**：結論の方向性は早く出すが、確定した答えは最後まで保留する。
- **1変化1保持**：図が変わったら約1.6秒保持する（銀座試作の目安）。説明の長さに合わせて調整する。
- **静止の活用**：複雑な図を読む間はカメラを止め、移動は場面導入・離脱に寄せる。
- **座標の共有**：地図・境界・地点印・ラベル・指示線は同じ変換で動かす。個別に動かすと対応が壊れる。
- **数字と図の分離**：数字を先に置き、その根拠の図を次の瞬間に出す。
- **冒頭への回収**：最後の一文を冒頭の言葉につなぎ、ループで再再生されやすくする。

なぜ効くか：離脱は「分からない」より「今どこを見ればいいか分からない」で起きやすい。変化を1つに絞り、保持時間を取り、動きを減らすことで、視聴者が考える余白が残る。

## 9. 行動を促す呼びかけ（CTA）

- 無意味な登録誘導は禁止。末尾のループ文は構成上のフックなので例外。
- チャンネル名「寄り道ラボ」を無理なく入れ、「また寄り道、続けます」のように音が冒頭へ戻る形にする。
- 概要欄には出典と利用条件、AI画像・AI映像を使った場合は「イメージです」と明記する。

なぜ効くか：CTAは「登録して」ではなく「次も同じ約束で続く」と示す方が、このチャンネルの文脈に合う。ループ文は視聴維持と次の再生を同時に狙える。

## 10. 完全な台本の作り方

`shorts-standard/PROMPT.md` に従い、JSONのみで出力する。キーは `title` / `hook` / `duration_sec` / `status` / `scenes` / `claims` / `needs_research`。各シーンは `start` / `end` / `narration` / `caption` / `visual` / `claim_ids` を持つ。

- 事実照合が未完了なら `status` は `needs_review`、`needs_research` に不足事項を書く。
- `claims` の `source_type` は `primary` または `ai_assistant`。`primary` は実在確認済みのURLとevidence_noteが必要。
- `python scripts/shorts_standard.py check <result.json>` でERRORが無くなるまで直す。WARNは内容を確認して判断する。
- `ready` のJSONだけを `to-spec` でレンダラ用specに変換する。

なぜこの順番か：形式検査は通っても事実が誤っていれば公開できない。逆に事実が正しくてもJSONが壊れていれば工程に渡せない。両方を別のゲートで確認する。

## 11. 各要素が視聴者を引きつける理由の整理

| 要素 | 視聴者の心理 | 効く仕組み |
| --- | --- | --- |
| 前提を崩すフック | 自分の思い込みが否定された | 立ち止まる |
| 答えの半分の先出し | 最後まで見れば揃う見通しが立つ | 離脱が減る |
| 1動画1疑問 | 話の主題が一つに絞られる | 考えないで見られる |
| 1変化1保持 | 今どこを見ればいいか分かる | 理解が止まらない |
| 数字と図の分離 | 数字の根拠が後で示される | 信頼が残る |
| 冒頭への回収 | 同じ約束で次も続く | ループ再生につながる |
