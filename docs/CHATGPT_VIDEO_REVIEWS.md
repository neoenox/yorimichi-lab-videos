# ChatGPT（web）による動画レビューの記録

観点は一つ：「YouTubeの視聴に耐えうるクオリティになっているか」。動画を確認用に圧縮して添付し、6項目（冒頭30秒／映像の変化／文字の読みやすさ／ナレーション／BGM・音量／構成と離脱箇所）を良い・普通・悪いで判定してもらう。
ナレーションとBGMの聴感は、ChatGPTは聴けないため毎回「確認できず」。聴感は人（ユーザー）が確認する。音量の数値（ピークなど）は、圧縮で変わるので、元ファイルを ffmpeg の ebur128 で測り直す。

## 手順（これで再現できる）
1. 長尺は `ffmpeg -vf scale=960:-2 -r 4 -c:v libx264 -crf 34 -preset veryfast -c:a aac -ac 1 -b:a 40k` で10MB未満に（17分で約7.7MB）。3分前後なら 1280幅・15fps・crf27・128k（約6MB）。
2. claude-in-chrome の `file_upload`（10MB未満、作業フォルダ内のパス）で https://chatgpt.com/ の新規チャットに添付→プロンプト送信（送信は右下の橙の矢印を座標クリック）。
3. 回答まで約4〜7分。3本まで並列（別タブ）で送れる。

## 共通の指摘（戦況解説・長尺）
- 結論・目玉（新史料など）を冒頭30〜60秒に出す。時系列の説明は後ろか、検証に必要な分だけに絞る。
- 地図は画面いっぱいに拡大し、部隊の動きを数十秒ごとに切り替える。地図内の小さい文字は大きくする。
- 小さい説明帯・細い枠・年表の文字は、スマホで読めない。一画面一メッセージにする。
- 『分からないこと』『まとめ』は短く。

## 戦況解説3本の作り直し（2026-11-01）
旧形式（紺の背景＋小さい地図＋細いパネル）を、ポップ形式＋大きな地図に作り直し、台本を圧縮した（17分→9分52秒、13分→8分38秒、13分→8分43秒）。
方法：`scripts/make_spec_<slug>.py` を書き換え（旧版は `*_before_pop.py`、台本の旧版は `09_script_v2_before_pop.md` に退避）。
- 結論・目玉を冒頭に（小牧＝朱印状の要点、山崎＝通説と新説、三方ヶ原＝『信長公記』に夜襲が書かれていない）。小牧は、朱印状の章を導入の直後へ。
- 旧パネル `pn()` → 右側の白いカード（`pop_rows`）。地図 `amap()` → 左に大きく。横長の地図は全幅＋カードを下に。地図の文字を2倍に。
- 地図の章ごとに、ぼかした背景イラストを敷く。終盤の『分かること／不明』は、一覧が消えてから、まとめを中央に。
- 落とした行は `DROP`（元の行番号→詰め直し）で、spec側の at/until を自動で直す。

## ビルドの注意
- `vp.py build` を `&` でバックグラウンドにすると、完了通知は『シェルの終了』で、ビルド自体は続いている。ログの `DONE` を待つこと。
- **ビルドは1本ずつ**。`vp.py build` は8並列でNVENCを使うので、複数のビルドを同時に走らせると「part render failed」になる。
- 失敗すると、古い映像のまま `pack` が通ることがある。`out/<slug>_video.mp4` の更新時刻が spec より新しいことを確認する。
