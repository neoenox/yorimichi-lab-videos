# 公開予約の一括解除と誤解除の記録（2026-11-25）

## 依頼と判断

オーナーから「長尺動画に誘導するショーツは一旦新規の公開はしないはず。調査していったんすべての公開予約を取り消して」と指示があり、確認の結果、対象は「`data/short_*.json` に `long_id` がある Short」、方針は「関連動画の設定が済んでいない Short は設定が完了するまで公開しない」と決まった。

## 実行したこと

- API 実測で予約が残っていた112件のうち、`long_id` を持つ109件の `publishAt` を解除した（`scripts/_cancel_scheduled.py --apply`）。成功109件、失敗0件。
- ただし、`long_id` の判定が甘く、`nolong: true` の単独Short（長尺と無関係）まで対象に含めてしまった。特に `qzxzekd5j-I`（43_bukka の長尺）は165本の spec にデフォルト値として入っており、実際の対応関係を表していない。

## 誤りの影響

- `nolong: true` かつ `long_id` あり：165件。このうち元々予約があり、誤って解除したものは67件と特定した。
- 復元スクリプト `scripts/_restore_nolong_schedule.py` を作成し、`--apply` を実行したが、YouTube API のクォータを使い切って途中停止した。
- 台帳では49件に `publishAt` が戻っている。API 側の反映は成功した可能性が高いが、クォータ超過のため読み戻し確認はできていない。
- 残り約18件は未復元。

## 今後の対応

- クォータは太平洋時間の深夜（日本時間の夕方ごろ）に回復する。回復後に `python scripts/_restore_nolong_schedule.py --apply` を再実行する。このスクリプトは、すでに予約が残っている動画はスキップするので、二重設定にはならない。
- 復元後、`scripts/_list_cancel_targets.py` で「long_id あり・nolong でない・予約あり」の件数を確認し、本来停止すべき168件（109−67＋...）だけが止まっている状態にする。
- 今回の誤判定を踏まえ、今後は `long_id` の有無だけでなく `nolong` フラグも見て対象を決めること。
