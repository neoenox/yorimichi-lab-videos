## 2. 原因の切り分け

### 原因1：長尺は「配られる面」に出ていない（これが本体）

公開して240時間（10日）で0再生は、**インプレッションがほぼ0**という意味です。サムネイルやタイトルの出来を測る以前の段階で、クリック率の良し悪しは数字に出ません。したがって「長尺のタイトル・サムネを改善しても再生は増えない」が、現時点の唯一の結論です。

根拠：0再生が6本、うち4本は公開から6日以上。1日でも経てば、チャンネルページ・検索・関連・ホームのどこからも1回も出ていない計算になります。

### 原因2：Shortsの1,200回は「床」であって、勝っているわけではない

13本が 993〜1,259 に収まっている＝**同じ大きさの試験配信を1回受けて、そこで止まっている**。ショートフィードは視聴維持とスワイプ回避率で次の配信を決めるので、全本が同じ帯に並ぶのは「内容の差が出ていない」というシグナルです。派手に当てにいくなら1本目3秒と最後のオチの設計ですが、**Shortsの数字を伸ばしても長尺の再生は自動では増えません**（流入元がショートフィード97〜100%で、そこからチャンネル登録以外の移動がほぼ無い）。

### 原因3：Short → 長尺の導線が、実質1本しかない

| 導線 | 実装状況 | 効いているか |
|---|---|---|
| Shortの概要欄に `youtu.be/<長尺ID>` | **あり**（`scripts/check_publish.py` が現IDかを検査、84/87のShort specが `long_id` を持つ） | ほぼ効いていない（Shortsでは概要欄を開かない） |
| Shortの「関連動画」に長尺を紐付け | **手作業**。13本中**10本**だけ済み（`data/related_done.json`）。長尺が公開された後でないと設定できない | 一部のみ |
| 長尺の概要欄 → 他の長尺 | **無し**（77本のspec全部にYouTubeリンクが1本も入っていない） | 0 |
| 終了画面・再生リスト | 未整備 | 0 |
| 固定コメント | 使っていない | 0 |

つまり「1,200人がShortを見た」のに、長尺へ移るボタンが**画面の1か所（関連動画）しかなく、しかもその設定が追いついていない**。0.20%という数字はこれで説明できます。

さらにタイミングの問題があります。現行は**長尺19:00 → Short20:00（同じ日）**。Shortの1,200回は公開後48時間に集中しますが、関連動画の設定は後日の手作業で、13本中3本がいまだ未設定です。**Shortがいちばん配られている48時間のあいだ、長尺への入口が空いていない**ことになります。

> 逆に「Shortを先に3日」という案は、この構造では不利です。関連動画に設定できるのは公開済みの長尺だけなので、Shortの山（公開後48時間）の時点で飛び先が存在しません。**長尺が先、Shortが後＝現行の順序が正しく、直すべきは「Short公開前に入口を付ける」運用**です。

### 原因4：供給が多すぎて、直す時間が無い

長尺15本/13日、予約は1.78本/日で52本が2027-01-23まで埋まっています。1日2本の日も2回ありました。作る速度が導線を直す速度を上回っていて、**0再生の動画を毎日1本ずつ増やしている**状態です。未予約のまま置かれている長尺8本も同じ理由で滞留しています。

### 原因5：タイトルが全部同じ型で、数字が無い

長尺15本すべてが「〜は、〜？」＋「〜で確かめる」。数字（年・秒・金額）が入っているのは**3/15**。一方Shortsは13/13に数字が入っています。長尺のタイトルは「調べる約束」しか書いておらず、**見た人に得する情報が無い**。検索でも狙える語（「日比谷入江」など）が入っていない回が多い。

（サムネイルは77本すべて別の背景画像を使っていて、使い回しではありません。ここは原因ではありません。）

## 3. 打ち手（効く順・対象ファイルつき）

### F1. 長尺公開の1時間後（Short公開前）に「関連動画」を設定する【最優先・クォータ不要】

- 19:00 長尺が公開 → **19:30までに** Short の「関連動画」にその長尺を設定 → 20:00 Short公開。これでShortの山（公開後48時間）の最初から入口がある。
- いまは「あとで設定する」運用なので、13本中3本が未設定のまま配られている：`maULwAgeB3Y`（江戸の夜道）, `JNRgZYi6jp8`（江戸の鐘）, `myjfHXMUQ-4`（降水確率）。3本とも長尺は公開済みなので、**いま設定できる**。
- 運用に落とす：`scripts/related_todo.py` を**毎日19:45**に実行し、`TODO` が出たらその場でStudioで設定 → `related_todo.py done <ShortのID>` で記録。
- 期待効果の目安：Short再生15,173 → 長尺31（0.20%）。入口が48時間ずっと開いていれば、1%台（150再生）は現実的な線。
- 追加の検証：設定が本当に効いたかは**関連動画経由の流入**をStudioで見る（アナリティクス → 視聴回数の流入元 → 「関連動画」）。48時間後に `data/studio_notes.md` へ。

### F2. Shortの固定コメントに長尺URLを置く（Studioで1クリック）

- Shortでは概要欄を開かないが、コメント欄は開かれる。**投稿はAPIでできるが「固定」はAPI非対応**（Studioで手作業）。
- quotaが回復したら `commentThreads.insert`（50ユニット/本）で投稿だけ自動化し、固定は手で押す、という分担が現実的。
- 本文の型：「くわしくは本編で →（長尺の問い）https://youtu.be/xxxx」

### F3. 0再生の長尺5本のタイトルを「数字＋結果」型に書き換える【50ユニット/本】

- `videos.update`（**50ユニット/本**）。サムネはそのまま、タイトルだけ。
- 例：`静脈の血は、体の中では青い？ アリゾナ州立大学とHarvard Healthで確かめる`
 → `静脈の血は青く見えるのに、取り出した血は赤い理由`
- 例：`家事を外注すると、GDPは増える？ 内閣府の資料で、数字を確かめる`
 → `家事を外注するとGDPは増える？ 無償労働を足すと日本のGDPは何％増えるか`
- 併せて、各specの `desc.title_main` を直してから再アップロードしない（メタだけ更新）。

### F4. ペースを落とす：長尺 週2〜3、Short 週3〜5

- 予約52本の長尺を1日1本で流すのをやめ、**週2〜3本**に間引く。空いた日に、F1〜F3とレビューを回す。
- 予約の間引きは `scripts/yt_api.py schedule`（各動画の公開日時を後ろへ動かす）で実施。**ただしquota（1本50ユニット）と、すでに告知済みかの確認が必要**。
- 未予約の長尺8本は、間引いた後の空き枠に「まとめて」ではなく**1本ずつ**入れる。

### F5. シリーズ化と社内リンク（回遊）

- 「東京の低地」（渋谷 → 日比谷 → 銀座 → 築地）のように**同じ地形・同じ画風**で3〜4本そろえ、再生リストに入れる。
- 長尺の概要欄に**次の長尺へのリンク**を入れる（いま77本すべて0本）。`scripts/make_spec_*.py` の `desc` に `series` 項目を足して、`videos.update` で既存にも反映。
- 終了画面は1本ずつ手作業（API非対応）。まずは再生リストだけでよい。

### F6. Shortsの1本目3秒（余力があれば）

- Studioの記録では継続率 32.5% / 20.7%。ショートフィードの伸びはここで決まる。ただし**F1〜F5より優先度は低い**（Shortsが伸びても長尺に流れない構造を先に直す）。
