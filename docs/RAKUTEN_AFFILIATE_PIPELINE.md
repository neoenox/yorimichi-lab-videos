- 作成: 2026-11-16（JST）。対象: 「楽天で売れている商品から逆算して AI 生成 Shorts を作り、アフィリエイトで収益化する」企画。

## 1. 結論（先に読む）

### 1.1 そのままでは通らないもの（設計から外す）

| 企画の工程 | 判定 | 根拠 |
| --- | --- | --- |
| 商品レビューをコピーして LLM に渡し、フックを作る | **不可** | ガイドラインが「**みんなのレビューを転載、転用、編集、複製すること**」を禁止行為に明記（更新日 2025/6/26）。転載だけでなく「編集」「複製」も入るため、要約して台本化する使い方も対象になり得る |
| 楽天の商品画像／AI で再現した商品画像を動画に焼き込む | **不可（実質）** | API 由来情報は「商品紹介＋リンク」目的に限定・**複製または改変禁止**。リンク作成ページの画像も「一部を切り取って使用」「画像上への文字・装飾」が禁止。動画への焼き込みを**許諾する明文は無い**。AI 再現はさらに商標・意匠・景表法（外観の誤認）が重なる |
| 「楽天ランキング1位」「レビュー1万件超え」を根拠なしに言う | **不可** | 景表法の優良誤認。ガイドラインも「いつ、どの範囲での記録なのかなどの根拠を表示せずに『ランキング1位！』」を禁止例に挙げる |
| 「料率アップ商品を API で自動抽出」 | **不可** | 料率アップ情報を返す API が提供サービス一覧に無い。確認手段は**ログインした管理画面の絞込のみ** |
| 化粧品・健康食品・健康器具でビフォーアフターや効能を出す | **不可** | ガイドラインが「使用前後の写真の掲載はNG」「身体に化粧品が浸透するような動画」を明記。薬機法の効能効果標ぼうにも触れる |
| Shorts の概要欄にリンクを貼って送客する | **不可（技術的）** | YouTube 公式が「ショート動画の説明に記載されている URL はクリックできません」と明記（§3.4） |
| AI で毎日決まった型の動画を量産する | **リスク高** | YouTube スパムポリシーが「AI を使用して類似したコンテンツを最小限の変更で大量に量産する行為」を例示。収益化停止・アカウント停止の対象（§3.5） |

### 1.2 通るもの（設計に残す）

- 「売れている商品から逆算する」という**選定思想そのもの**は有効。ただし選定に使える材料が、レビュー本文ではなく**商品名・価格・ジャンル・レビュー件数などの数値メタデータ**に限られる。
- **アフィリエイトリンク自体は YPP と無関係に作れる**（`hb.afl.rakuten.co.jp`）。ただし置き場所が限られる。**Shorts の説明欄は踏めないので、当面はチャンネルプロフィールのリンク（楽天 ROOM 等）が唯一の現実的な導線**（§3.4）。
- 動画内の商品タグ付け（YouTube ショッピング）は規約上は可能だが、**YPP 参加が前提**。新チャンネルでは当面使えない。
- AI 生成してよいのは「商品そのもの」ではなく**商品を使った後の情景・悩みの情景**（§3.2）。

## 2. 実測でわかったこと（2026-11-16）

### 2.1 料率と上限（公式ガイドライン・更新 2025/6/26）

- 基本料率は**ジャンル別 2〜4%**。商品紹介で扱いやすい **家電 2%／キッチン用品・食器・調理器具 3%／日用品雑貨 3%／食品・コスメ・ファッション 4%**。上記以外は 2%。
- 上限は**1商品1個あたり 1,000円**（買い物かご1個単位で判定。複数購入の合計が 1,000円を超える場合は上限なし）と、**同一ユーザー月 3,000円**。
- 成果発生条件は「クリック後 **24時間以内に買い物かご**、**89日以内に購入完了**」。動画→購入のタイムラグはこの範囲で拾われる。
- 報酬は**楽天ペイ残高**での受取が基本。銀行振込は「3カ月連続で月間3,001円以上」が条件。

### 2.2 料率アップ（この企画の生命線）

公式記載は次のとおり。

- 適用料率は **5〜20%（1%ごと）**。対象は「**対象ショップの対象商品ジャンルの全商品**」。
- **料率アップ対象商品は 1商品1,000円の上限も、同一ユーザー月3,000円の上限も外れる**（明記）。
- ただし「パートナー様により適用される料率が異なる」「売上等が一定基準を超えるパートナーにはショップがより高い料率を提供する場合がある」「**売上等に関係なく、一部のパートナー様は料率アップ対象外**」「上記の基準は**いずれも非公開**」。
- 更新は毎日0時、ショップにより最短2週間で料率が変わる。

**設計上の意味**: 料率アップは「商品の属性」ではなく「**パートナー×ショップ×ジャンルの関数**」であり、しかも判定基準が非公開。したがって**「高料率だからこの商品を選ぶ」を機械的に自動化することはできない**。実務は「管理画面で料率アップ商品を絞り込み、人手で候補を拾ってキューに投入する」半自動になる。

### 2.3 API（実測ログ）

`webservice.rakuten.co.jp`（仕様書・利用規約）は参照日 **HTTP 503** で本文が取れなかった（同日、管理画面は 2026-11-09 からメンテナンス停止中という公式告知あり）。代わりに**ゲートウェイを直接叩いて**次を確認した。

```
$ curl 'https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701?format=json&keyword=test'
400  {"errors":{"errorCode":400,"errorMessage":"applicationId must be present in the query parameter or request body"}}

$ curl 'https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701?applicationId=dummy&format=json&keyword=test'
400  {"errors":{"errorCode":400,"errorMessage":"accessKey must be present as a query parameter or in the header"}}

$ curl 'https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701?applicationId=dummy&accessKey=dummy&...'
403  {"errors":{"errorCode":403,"errorMessage":"Invalid Access Key"}}

$ curl 'https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Review/20260701?...'
404  {"statusCode":404,"message":"Resource not found"}
```

読み取れること（**確度の高い順**）:

1. **新ゲートウェイは `openapi.rakuten.co.jp`、サービス別プレフィックスは `ichibams/api`（検索系）と `ichibaranking/api`（ランキング系）。** 経路が無ければ 404、認証が通らなければ 403、パラメータ不足は 400 で返る（この3つは実測で判別できる）。
2. **`applicationId` と `accessKey` の2つが必須。** 旧来の applicationId 単独では通らない。
3. **レビュー系の経路は存在しない**（404）。→ 動画のフックをレビューから作る工程は、規約以前に**技術的にも組めない**。
4. レート制限は **1 application_id あたり 1秒1回以下**、緩和申請は不受付。**1日あたりの上限は公式 FAQ に見当たらない（未確認）**。
5. 料率アップ一覧・レビュー本文を返す API は、提供サービス一覧（楽天市場／ブックス／トラベル／レシピ／Kobo／GORA）に無い。

旧ドメイン `app.rakuten.co.jp` も 2026-11-16 時点で応答し、`IchibaItem/Search/20220601?applicationId=dummy` に `{"error":"wrong_parameter","error_description":"specify valid applicationId"}` を返した。ただし公式ブログは旧バージョンを「`API Configuration not found` を返す」と告知しており、**有効な applicationId を持たない状態では「生きている」と「廃止済みで設定が見つからない」を区別できない**。実データ取得での確認は未了（§7）。

### 2.4 画像（最重要）

- API 由来の情報は「利用者ソフトウェア上で当社の商品を紹介し、かつ当社内の当該商品のページにリンクを設ける目的」に限定され、**この目的以外での複製・改変は禁止**。
- アフィリエイトリンク作成ページからダウンロードした画像は**サイズ変更・周辺加工は可**、しかし「**画像の上に直接文字や装飾を入れること、画像の一部を切り取って使用することは禁止**」。
- 動画での利用（焼き込み）を**許諾する明文は無い**。禁止の明文も無いが、パートナー規約 第10条（明文で許諾された以外の権利は付与しない）と第5条4項（リンク作成用コンテンツの目的外使用禁止）を踏まえると、**リスクは高い側に倒れる**。
- 個別の可否判断は楽天も行わないと明言している（「特定の行為が規約に抵触するかについては個別の回答は行っておりません」）。

**設計上の意味**: 9:16 の全面背景に商品画像を置く＝「一部を切り取って使用」に該当し得る。**商品画像を動画素材にする設計は捨てる**。

### 2.5 代替になる公式の見せ方

- **概要欄テキストリンク**（リンク作成ページで「テキストのみ」を選ぶと、商品名を含むテキスト部分のみ編集可）。概要欄に貼るのはこれ。
- **楽天ROOM**（投稿は公式 UI のみ、API なし）。ROOM 経由は「通常報酬＋ランクボーナス S:3%／A:2%／B:1%」。
- **モーションウィジェット**はブログ埋め込み用の JS で、動画には使えない。

### 2.6 YouTube 側（**別チャンネルで運用する前提**）

アフィリエイト用 Shorts は**既存の「寄り道ラボ」とは別チャンネル**で出す方針（2026-11-16 オーナー判断）。以下は参考として既存チャンネルの実測を残すが、**新チャンネルには当てはまらない**。

2026-11-16 に YouTube Studio の収益化ページで確認（表示データは 2026-11-11 時点）。

| 項目 | 現状 | YPP 参加要件 |
| --- | --- | --- |
| チャンネル登録者 | 54人 | 500人（ショート動画枠）／1,000人（通常枠） |
| アップロード動画数 | 3本 | 3本 |
| 有効な総再生時間（365日） | 3時間 | 3,000時間 |
| ショート動画の視聴回数（90日） | 1.9万回 | 300万回（ショート枠）／1,000万回 |

→ **収益化は未達**。Studio 上で「ショッピング」は収益化プログラムの一つとして表示されるため、**動画内の商品タグ付けは YPP 参加後**という扱いになる見込み（YouTube ヘルプの一次確認は §7 の未確認項目）。

**新チャンネルではさらに遠い**: 登録者0からのスタートになるので、YPP 到達まで YouTube ショッピングは使えない前提で組む（§3.4 の導線設計を参照）。

#### 2.6.1 別チャンネル運用で先に片付けること（コードの実測）

既存の投稿パイプラインは**1チャンネル前提でハードコードされている**。

- `scripts/yt_api.py:34` `CHANNEL_ID = 'UCN_do9fcssctmkrNsRWOO9A'  # 寄り道ラボ`。以降の全操作（アップロード／予約／削除）で `mine(yt)` にこのIDが含まれるかを検査し、違えば「個人チャンネルへは上げません」と停止する。
- `scripts/studio_cdp.py:21` も同じ定数を持ち、URL に含まれなければ停止する（誤操作防止）。
- 認証情報は `secrets/token.json`、投稿台帳は `data/youtube_ids.json`。**どちらも1チャンネル分**。

→ 別チャンネルを使うには、(a) `CHANNEL_ID` を設定ファイル／引数化し、(b) チャンネルごとに別の OAuth トークンと台帳を持つ、(c) 誤投稿防止のガードは**チャンネルごとに維持**する、の3点が必要。ガードを外して使い回すのは事故のもとなので避ける。

また、**楽天アフィリエイトのサイト情報には、リンクを貼る先（新チャンネル）を登録する**必要がある。チャンネル作成 → サイト登録 → リンク作成、の順になる。

## 3. 企画の修正（v2）

### 3.1 「レビュー起点」を「メタデータ起点」に置き換える

- 使える材料: 商品名・価格・ジャンル・ショップ名・レビュー**件数／平均点**（数値のみ）・送料・画像 URL（表示には使わない）。
- 使えない材料: レビュー**本文**（規約で転載・編集・複製禁止、API にも存在しない）。
- 悩み・共感のフレーズは**こちら側で書く**。根拠が要るのは「数字・固有名詞・因果関係」だけで、「夕飯を作ろうとしたら肉が凍っていた」という一般化された情景描写は事実主張ではない。

### 3.2 商品画像を捨てる代わりに、何を見せるか

| 見せたいもの | 使うもの | 条件 |
| --- | --- | --- |
| 商品そのもの | 実写（自分で買って撮る） | 撮影は自由。メーカーの意向は別途確認 |
| 商品を使った後の理想の状態 | AI 生成 | 「イメージ」と画面に明記（`shorts-standard` の既存ルールと同じ） |
| 商品の存在・価格・リンク | テロップ＋チャンネルプロフィールのリンク | 数値は商品ページを一次資料にする。Shorts の説明欄 URL は踏めない（§3.4） |
| 商品名だけ | 文字 | 商品名・メーカー名を正しく表す限り使用可（ガイドライン明記） |

**「商品が映らない動画」を前提に設計する。** これは制約であると同時に、量産とコストの面では有利（撮影が不要）。

### 3.3 台本の型（既存の `shorts-standard` を壊さずに使う）

既存標準は「疑問→結論の方向性→理由・根拠→結論回収」で、claims に一次資料 URL を要求する。商品系でも**商品ページ URL を一次資料にすれば通る**（レビュー件数・価格・素材は商品ページに書かれている）。

- `claims[].source_type: primary` の `source_url` ＝ その商品の楽天商品ページ URL。
- 動画で言ってよい数値は、**商品ページ／メーカー公式ページに書かれている範囲のみ**。体験談ベースの「6倍速い」等は、その表現が商品ページに無ければ言わない。
- 「PR」を全編表示する（§3.6）。

### 3.4 CTA（ここが企画の最大の穴）

**Shorts の説明欄に貼った URL はクリックできない。** YouTube 公式ヘルプに明記がある（2026-11-16 取得）。

> 注: スパムや詐欺行為を減らすため、ショート動画のコメントやショート動画の説明に記載されている URL はクリックできません。
> （出典: <https://support.google.com/youtube/answer/13748639?hl=ja>）

同ページの一覧で「クリック可能」に分類されているのは、**チャンネルプロフィールのリンク／外部ブランド案件のリンク／長尺動画のコメントや説明の URL（上級者向け機能の有効化が必要）／ショート動画からリンクされた関連動画／YouTube ショッピング アフィリエイト プログラムのリンク／投稿（コミュニティ）／終了画面**。

したがって Shorts 単体で「概要欄から商品ページへ」という設計は**成立しない**。取り得る導線は次の3つ。

| 導線 | 前提 | 強さ | 備考 |
| --- | --- | --- | --- |
| **チャンネルプロフィールのリンク**（楽天 ROOM 等） | なし | 弱〜中 | 14 件まで。動画内で「プロフィールのリンク」と言及する必要がある |
| **長尺動画の説明欄**（Shorts → 関連動画 → 長尺） | 電話番号認証などの上級者向け機能 | 中 | 二段階になるが、リンクは踏める |
| **YouTube ショッピングの商品タグ** | **YPP 参加**（登録者 1,000 人＋4,000 時間、または 90 日 1,000 万 Shorts 視聴） | 強 | 新チャンネルでは当面届かない |

**企画への影響**: 「Shorts を量産して概要欄から送客」は物理的に不可能。当面は**プロフィールリンク（楽天 ROOM）へ寄せる**しかなく、転換率はかなり低く見積もる必要がある（§5）。ショート動画の元案が「プロフの楽天 ROOM へ」としていたのは、結果的にこの制約に合っている。

なお **「クリックして」「お願いします」と嘆願する表現は楽天ガイドラインで禁止**（閲覧者に対しクリックを依頼又は嘆願する行為）。

### 3.5 量産しない設計（自動化の範囲を絞る）

YouTube のスパムポリシーは、まさにこの企画の量産方式を名指しに近い形で例示している。

> 自動化ツールや AI を使用して、類似したコンテンツを最小限の変更で大量に量産する行為（例: 多数の動画でまったく同じ BGM や単調な AI 生成画像を使い回し、AI 作成の台本を読み上げているだけのチャンネル）
> （出典: <https://support.google.com/youtube/answer/2801973?hl=ja>）

違反時の制裁は「チャンネルの収益化の一時停止」「チャンネルまたはアカウントの停止」。したがって、

- **「同じ型の動画を毎日10本」は取らない。** 週数本に抑え、題材ごとに素材・編集・語りを変える。
- パイプラインの自動化対象は**下書き生成と検査まで**。最終的な採否と構成は人が決める。
- 定型 BGM・定型背景の使い回しを避ける（既存リポジトリの `art_map.json` でシーンごとに背景を変える運用と整合）。

### 3.6 「PR」表示（ステマ規制）

- ステマ告示（令和5年内閣府告示第19号、2023-10-01 施行）の「事業者の表示」に、**アフィリエイトプログラムを用いてアフィリエイターに表示させる場合**が明記されている。
- 動画は「**冒頭に『広告』と表記するだけでは足りない**」とされ、画面に常時表示することが望ましいとされる（消費者庁 Q15）。→ **動画の全編を通して画面の隅に「PR」を出す**。
- サムネイル・固定コメント・説明欄冒頭にも「PR」を置く。

## 4. パイプライン設計

```
[1] 候補収集      管理画面の料率アップ絞込（人手）＋ API のランキング／検索
      ↓
[2] 選定          スコアリング（料率は人手フラグ、需要はメタデータ）
      ↓
[3] 台本生成      LLM に渡すのは「商品メタデータ＋一般化した悩みの型」（レビュー本文は渡さない）
      ↓
[4] 検証          short-standard の check（claims/一次資料）＋ 法規 NG 語チェック
      ↓
[5] 画像生成      情景のみ（商品そのものを描かせない）
      ↓
[6] 描画         既存の vp.py / make_short2.py 系 ＋ 「PR」を全編オーバーレイ
      ↓
[7] 投稿・導線   新チャンネルへ投稿。プロフィールリンク（楽天ROOM等）を整備
      ↓
[8] 計測         再生は YouTube Analytics、成果は楽天アフィリエイトのレポート（サイト単位）
```

**計測の限界**: Shorts からプロフィール経由で飛ぶため、**動画単位の成果は原理的に取れない**。楽天側のレポートはサイト（チャンネル）単位の集計になる。どの動画が効いたかは「投稿日の前後比較」でしか見られない。

### 4.1 候補収集

- API で取るのは**ランキング（`ichibaranking/api/IchibaItem/Ranking`）と検索（`ichibams/api/IchibaItem/Search`）**。
- **レート制限 1秒1回**なので、1日 1,000 件規模の収集は 20 分程度。バッチは夜間に回し、結果をキャッシュする（価格は 24 時間、その他は 3 か月のキャッシュが規約上許容）。
- 料率アップの候補だけは**管理画面から人手でエクスポート**（自動化不可、§2.2）。

### 4.2 選定スコア

自動化してよいのは需要側の指標のみ。

- レビュー件数（多いほど購入判断の材料がある）
- 平均評価（4.3 以上など）
- 価格帯（§5 の収益計算に効く）
- ジャンル（**家電 2%／キッチン 3% は料率が低い**ことをスコアに織り込む）

料率は「人手で付けるフラグ」として別列に持つ。**自動スコアに混ぜない**（更新が毎日変わり、判定基準が非公開のため）。

### 4.3 台本生成

LLM への入力は次の3つに限定する。

1. 商品メタデータ（名前・価格・ジャンル・レビュー件数・平均点・ショップ）
2. 商品ページに書かれている**仕様・特徴の要約**（転載ではなく、こちらの言葉に直す）
3. 「悩みの型」のテンプレート（例: 冷凍肉の解凍が間に合わない／充電ケーブルが絡まる）

出力は既存の `result.json` 形式＋ `disclosure: "PR"` を持たせる。

### 4.4 検証（ここが自動化の要）

既存 `shorts_standard.py check` に加えて、商品系専用の検査を足す。

- `source_url` が実在し、`item.rakuten.co.jp` の商品ページであること
- 台本中の数値が `evidence_note` に引用されていること
- NG 語（効く／治る／痩せる／シワが消える／ランキング1位／最安 等）の検出
- 「PR」表記の存在
- レビュー本文らしき長文引用が無いこと

### 4.5 画像

商品を描かせない。プロンプトに「特定の実在商品を描かない／ロゴを描かない」を明示し、出力後に NG 判定（ロゴ・実在商品名の混入）を人目で確認する。

## 5. 収益の現実的な見積り（仮定つき・断定ではない）

**すべて仮定**。実測ではない。新チャンネル（登録者0）を想定する。

| 段階 | 仮定 | 月間 |
| --- | --- | --- |
| Shorts 再生 | 月10本 × 1本3,000回 | 30,000 |
| プロフィールへ移動 | 再生の 3% | 900 |
| プロフィールからリンクをクリック | 移動の 30% | 270 |
| 購入 | クリックの 2% | 約 5.4 件 |
| 報酬（単価3,000円・料率3%） | 1件 90円 | **約 490 円** |
| 同上で料率アップ20%が効いた場合 | 1件 600円 | **約 3,200 円** |

読み方:

- **Shorts の説明欄が踏めないことが、そのまま一段の目減りになる**（§3.4）。長尺動画ならリンクまで1クリックなので、同じ再生数でも桁が変わる。
- 差を生むのはほぼ**料率**。再生数を伸ばすより料率アップ商品を拾うほうが効くが、その適用可否は非公開基準（§2.2）。
- 料率アップ20%が効くケースでも**月数千円規模**。YPP 参加（動画内タグ付け）に到達するまでは、収益より「チャンネルの立ち上げ」を目的に置いたほうが現実的。

## 6. 人間が先に確認すること（自動化できない前提条件）

1. **新チャンネルの作成と、楽天アフィリエイトへのサイト登録**: アフィリエイトリンクを貼る先をサイト情報として登録する。登録前のリンク設置は規約上できない。
2. **投稿パイプラインの2チャンネル対応**: `CHANNEL_ID` の外部化、チャンネル別トークン・台帳の分離（§2.6.1）。
3. **リンクの置き場所**: Shorts の説明欄は踏めないので（§3.4）、チャンネルプロフィールのリンクを整備する。長尺動画を併走させるなら上級者向け機能（電話番号認証等）の有効化も必要。
4. **料率アップの適用有無**: 管理画面の料率アップ商品一覧で、自分のアカウントに表示される料率を確認する（ログインしないと見えない）。新チャンネルは実績ゼロなので、**料率アップの対象外になりやすい**点に注意。
5. **YouTube ショッピングの資格**: YPP 参加後に改めて確認（新チャンネルでは当面使えない）。
6. **API キー**: `openapi.rakuten.co.jp` 用の applicationId と accessKey。管理画面が 2026-11-09 から停止中で、**新規発行ができない可能性がある**（復旧状況は要確認）。
