# モデル比較検証：同じ台本で動画を作らせる（Sonnet 5.5 / GPT-6 Luna / DeepSeek V4.1 Flash）

目的：台本・素材・制作ラインを固定し、「画面づくりと仕上げ」をモデルだけ変えて行わせ、品質・手間・コストを比べる。
注意：比べるのは「台本から動画にするまでの作業」。台本そのものを書く力は、この検証の対象外（台本は固定）。

## 1. 条件（3モデルで完全に同じにする）
| 項目 | 内容 |
|---|---|
| 台本 | 下の「2. 台本」。**1文字も変えさせない** |
| 素材 | 下の「3. 共通素材」。同じ画像・同じBGM曲 |
| 制作ライン | `scripts/vp.py`（`docs/VIDEO_PIPELINE_VP.md`）、画面は `style=pop` |
| 事前確認 | `docs/VIDEO_CREATION_PRECHECK.md` を全文読んでから着手（AGENTS.md の決まり） |
| 守る決まり | `docs/VIDEO_PRODUCTION_RUNBOOK.md` の「ユーザーからの指摘と、動画づくりの決まり」 |
| 作る場所 | slug を分ける：`sigsonnet` / `sigluna` / `sigdeepseek`（**slugに下線を入れない**） |
| 人の手直し | **なし**。モデルが自分で `still`・`qa` を見て直す。人は指示を出さない |
| 上限 | 3モデルとも同じ：やり直し（再ビルド）は3回まで、作業時間は2時間まで |
| 同時実行 | ビルドは1本ずつ（動画の書き出しの同時セッション数に上限があり、並べると失敗が混ざる） |
| 記録 | 開始・終了時刻、再ビルド回数、トークン数または料金、止まった箇所を `docs/MODEL_COMPARISON_LOG.md` に書く |

### モデルに最初に渡す指示文（3モデル共通・そのままコピー）
```
あなたは動画制作ライン scripts/vp.py を使って、1本の解説動画（約3分）を作る担当です。
作業を始める前に docs/VIDEO_CREATION_PRECHECK.md を全文読み、docs/VIDEO_PIPELINE_VP.md と
docs/VIDEO_PRODUCTION_RUNBOOK.md の「動画づくりの決まり」を読んでください。
台本は docs/MODEL_COMPARISON_BRIEF.md の「2. 台本」です。1文字も変えてはいけません。
slug は <指定のslug> です。次を作ってください：
 1) data/<slug>_pronunciations.json（読み）
 2) scripts/make_spec_<slug>.py と data/<slug>_spec.json（style=pop。章ごとに図かテロップ。素材は「3. 共通素材」のみ）
 3) vp.py で story → kana → audio → bgm → build まで
 4) vp.py <slug> still で場面を確認し、字幕との重なり・文字の見切れ・肖像や図の隠れを直す
 5) 終わったら、確認できたこと／確認できていないことを分けて報告する。
視聴品質や投稿可能を、デコードに成功しただけで宣言してはいけません。
```

## 2. 台本（固定）
題材：信号の「青」は、なぜ緑色に見えるのか。約3分、26文、6章。

〔Kn〕は根拠の番号。`at` は台本の行ではなく「文」の番号（`vp.py <slug> sents` で確認）。

### 章1 intro「信号の青は、緑じゃない？」
1. 信号の青は、本当は緑色に見えませんか。
2. 青信号と呼ぶのに、見た目は緑に近い。
3. これは、日本語の「青」の歴史から来た呼び方だとされます。
4. 今回は、その理由を、法令と言葉の面から確かめます。

### 章2 law「法令では何色？」
5. まず、法令です。
6. 道路交通法施行令では、信号の灯火の意味を「青色の灯火」と書いています。〔K1〕
7. つまり、法令上の名前も「青色」です。
8. 一方で、実際に光る色は、緑のなかでも青みの強い色にされているとされます。〔K2〕
9. 名前は青、見た目は緑寄り。ここにずれがあります。

### 章3 history「日本初の信号機」
10. 日本で、3色の灯火を使う信号機が日比谷交差点に置かれたのは、1930年とされます。〔K3〕
11. 進めの合図を「青」と呼ぶ言い方は、その後、広く定着しました。
12. 英語の呼び名は、グリーンライトです。
13. 日本語だけが、わざわざ違う名前を付けたわけではありません。

### 章4 language「言葉の『青』」
14. 日本語の「青」は、昔は、緑も含む広い色の名前だったと考えられています。〔K4〕
15. 青葉、青菜、青りんごのように、緑のものにも「青」が付きます。
16. 古い日本語には、色を表す基本の言葉が、あか、くろ、しろ、あおの4つだったという説があります。〔K4〕
17. 信号の青も、この使い方を受け継いだ名前だと説明されます。

### 章5 world「他の国では？」
18. 他の言語でも、青と緑の区別は一様ではありません。
19. 韓国語では、青信号を「パランブル」と言い、青い火という意味の言葉を使います。〔K5〕
20. ベトナム語には、青と緑の両方を指す色の言葉があります。〔K5〕
21. 色の名前の切り方は、言語によって違うのです。

### 章6 end「結論」
22. 結論です。
23. 青信号の「青」は、色の見た目ではなく、日本語の「青」の使い方を受け継いだ名前と考えられます。
24. 法令の名前も青色で、光る色は緑寄りです。
25. だから、青信号が緑に見えるのは、間違いではありません。
26. 信号を待つ間に、ぜひ思い出してください。

### 根拠（概要欄用。ここは3モデルとも同じ文面を使う）
| 番号 | 内容 | 状態 |
|---|---|---|
| K1 | 道路交通法施行令 第2条（灯火の意味。e-Gov法令検索） | 条文で確認できる |
| K2 | 信号灯器の色の規格（警察庁／JISの交通信号灯器） | **未確認**（概要欄に明記） |
| K3 | 日本初の3色灯式信号機は1930年・日比谷交差点（警察庁・警視庁の沿革） | **未確認**（「とされる」で語る） |
| K4 | 古い日本語の色名「あか・くろ・しろ・あお」説（国語辞典「あお」の項、大野晋の説） | **未確認**（有力説として語る） |
| K5 | 韓国語 파란불、ベトナム語 xanh（辞書） | **未確認** |

方針：有料書籍・紙資料は深追いしない。未確認は概要欄に明記して進める（`give-up-hard-verification` の方針）。
この検証では、事実の正確さは比べない（台本が同じため）。

## 3. 共通素材（3モデルとも、これだけを使う）
- 背景イラスト：**ChatGPT（web）で1回だけ作り、3モデルに同じ3枚を渡す**。保存先 `assets/sigcmp/art_intro.png`（信号機のある交差点の夜）、`art_law.png`（青緑に光る信号機のアップ）、`art_world.png`（世界地図に色とりどりの吹き出し）。文字は入れさせない。依頼文は検証開始前に私が書く。
- BGM：`assets/bgm_maou/` のうち同じ2曲に固定（spec の `bgm` に同じ指定を書かせる）。
- 音声：VOICEVOX、同じ話者・同じ速度（`vp.py audio` の既定のまま）。
- サムネイル：この検証では比べない（作らない）。

## 4. 評価（動画ができたら）
### 4-1. 機械で測れるもの（自動）
| 指標 | 方法 |
|---|---|
| 最後まで作れたか | `vp.py <slug> build` が通り、`qa` が通る（黒フレーム・長さ・音量） |
| 台本が変わっていないか | 字幕（SRT）を結合し、固定台本と差分を取る（句読点の間引きは許容） |
| 読み間違い | `kana` の結果を全文確認し、誤読の数を数える |
| 字幕と画面の重なり | 毎章4か所の静止画で、字幕帯（y≥836）に画面文字がかかる数を数える |
| 見切れ・折り返し | 文字が枠や画面外にはみ出す数、1文字だけの折り返しの数 |
| 手戻り | 再ビルド回数、止まった箇所の数、人の介入（0であるべき） |
| 時間・費用 | 作業時間、トークン数または料金 |

### 4-2. 人が見るもの（目隠し）
- 3本を **A/B/C にして並べ替え**、モデル名を隠したまま見る。
- あなたが、下の5項目を各1〜5点で採点（通しで視聴）。
  1. 画面の見やすさ（文字の大きさ・重なり・読みやすさ）
  2. 台本に合った絵になっているか（語りと画面が合う）
  3. 変化・退屈しにくさ（場面の切り替え、図の動き）
  4. 全体の仕上がり（テロップ・色・統一感）
  5. 「このまま公開してよい」と思うか
- 併せて、ChatGPT（web）の通し視聴レビューも1本ずつ取る（既存の手順。モデル名は隠す）。

### 4-3. 総合
- 自動指標（4-1）と目隠し採点（4-2）の平均を並べる。
- 見るのは「点数の高さ」だけでなく、**人の手直しゼロで公開候補に届いたか**と、**同じ品質を出す費用**。

## 5. 公平にするための注意
- 同じ日に、同じ状態のリポジトリ（同じコミット）から始める。作業用に `git worktree` か、slugごとの出力先で混ざらないようにする。
- 順番の影響を避けるため、実行順は Luna → Sonnet → DeepSeek のように固定せず、くじで決める。
- 誰かが失敗した部分を、別のモデルの成果物から写させない（互いの `data/` を見せない）。
- 失敗したら、そのまま失敗として記録する（やり直しは上限の3回まで）。
- 1回の結果は偶然を含む。余裕があれば、題材を変えてもう1本（別の台本）で再度試す。
